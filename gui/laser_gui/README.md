# AC-LGAD レーザースキャン制御 GUI (`laser_gui_v4`, 2026-11-01 版)

> **公開版について**: このリポジトリでは、装置の IP アドレス・ユーザー名などを
> `<SCOPE_IP>` / `<STAGE_IP>` / `<PC_IP>` / `<GATEWAY_IP>` / `<SCOPE_USER>` /
> `<SCOPE_WIN_USER>` などのプレースホルダに置き換えています。実機で使うときは
> `config_local.example.json` を `config_local.json` にコピーし、実際の値を書いてください
> (実際の値は Hiroshima TCT Wiki の内部向けページにあります)。`config_local.json` は git 管理外です。

AC-LGAD の TCT レーザースキャン評価システムを**暗室に入らずに**操作するための
フロントエンド GUI。装置の電源投入後、この GUI だけで
「照射位置決め → レーザー照射 → 波形確認・保存」が完結することを目的とする。

対応機器 (guide/ の仕様書・接続図に基づく):

| パネル | 機器 | 接続 | 既定アドレス |
|---|---|---|---|
| オシロスコープ | Teledyne LeCroy WavePro | LAN (VICP ネイティブ実装 / VXI-11) | `VICP::<SCOPE_IP>::INSTR` |
| ステージ | OptoSigma SHRC-203 (3軸) | LAN (TCP) または RS-232C | `<STAGE_IP>:9004` |
| レーザー | NKT Photonics PiLAS DX (EGI-D2-40) | USB 仮想COM (19200 8N1, CR終端) | `COM5` (解析用PCで実測確認済) |
| カメラ | フォーカスカメラ (USB) | OpenCV (Windows は DirectShow 優先) | device 0 |

GUI は 16:9 横長モニター (解析用PC: EX-LDHU431DB) 向けの 3 カラム構成
(左: オシロ+通信ログ / 中: カメラ+ステージ / 右: レーザー+スキャン)。
起動時にモニターの利用可能領域内へ自動的に収まる。

| **ピクセル解析** | kind `pixel` (`analysis\analyze_pixel.py` → `macro\template_timing\tt_pixel.py`): 振幅マップ、2/3/4 ピクセル合成の時間・位置分解能、立ち上がり、ジッター、伝搬 (pix01–06)。解析パッケージの詳細は `analysis\README.md` |

## 測定標準条件 (2026-07 実測で確定)

`config.py` に既定値として登録済み。オシロパネルの
「★ 標準設定を一括適用 ★」ボタンで下記のオシロ設定を一括送信できる。

- **オシロトリガー**: Ext, DC, positive, 410 mV
- **縦軸**: 50 mV/div, offset +100 mV (表示範囲 -300 〜 +100 mV)
- **横軸**: 1 ns/div, offset **-53 ns** (表示範囲 +48 〜 +58 ns)。
  AC-LGAD 信号はレーザートリガーの約 52 ns 後に来る (2026-10、1 MHz で
  実測)。旧設定 -4 ns で見えていたのは 40 MHz (周期 25 ns) で 2 周期後の
  トリガーに対する同じ信号が 52 − 50 = +2 ns に折り返していたため。
  -53 ns なら TCT 推奨の 1.25 MHz を含めどの繰り返し周波数でも同じ窓に
  信号が入る (`config.py` の `scope_trig_delay`)
- **チャンネル**: C1〜C4, DC 50Ω
- **AC-LGAD バイアス** (GUI 制御外, ステータスバーに表示): HV = -185 V, LV = 6.0 V
- **読み出しチャンネル対応** (標準センサー): C1=J8, C2=J7, C3=J6, C4=J5
  (センサープロファイルごとに設定。下記「センサー / DUT の登録」)
- **ストリップ位置** (標準センサー, 2026-08-24 実測 = 治具改良後。
  論理座標 [µm] で記録し、機械座標は論理原点の機械座標を加算して再構成。
  詳細は `scan_geometry.py`。標準センサーのプロファイルの初期値になる):
  - **X=0 = センサー外枠 (GND) エッジ** (2026-09-07 定義変更。
    "Strip detail" スライドの内訳 ⓪0.052 + ①0.380 + ②0.200 (パッド)
    + ③9.318 (ストリップ露出) + ④0.098 (端ギャップ) mm)。
    ストリップ露出部は論理 X = −632 〜 −9950 µm、**原点から −10 mm で
    ギャップ④中央 (2 ストリップ領域の境界)** に来る。
    論理原点の機械座標 (2026-08-24 実測の +632 µm 換算):
    **(108932, 100050, 1414)**
  - Y (ストリップ横断): C0端 100550 → C5端 98050 (ピッチ 500 µm ちょうど)。
    読み出しは C1–C4、C0/C5 はその外側の非読み出しストリップ
  - X (ストリップ長手, 露出部読み出し側端→反対側): 108300 → 98982
  - Z (レーザーフォーカス): 1406〜1416 (センサー傾きにより位置依存)
  - **センサー傾き** (面フィット, 残差 ±1.6 µm): フォーカス面
    dZ/dX = −0.02 (ほぼ平坦), dZ/dY = +3.79 µm/mm / 面内回転
    dY/dX = +7.7 µm/mm (ストリップ全長で Y が ~72 µm ドリフト)。
    自動スキャンはこの傾きを相対移動で自動補正する (下記)。
  - 絶対座標は M-ORG のたびに変わり得るため目安。スキャンは論理原点
    基準の相対移動で行い、絶対座標に依存しない。
- **レーザー** (2026-11-01 標準化): トリガー **internal**、繰り返し周波数
  **1 MHz** (旧標準の TCT 推奨 1.25 MHz から変更。水平オフセット −53 ns
  も 1 MHz 実測値)、TUNE **manual 50 % = MIP 相当の出力** (隣接 2ch 合計を
  ストリップ中間で DESY ビームテスト 2026 の 64 mV に合わせた値。
  2026-10-19 の HV 依存測定も tune 50 %)。レーザーパネルの
  「★ 標準設定を適用 ★」で一括送信 (`config.py` の `laser_freq_hz`,
  `laser_tune_auto`, `laser_tune_percent`)。auto TUNE はコントローラの
  周波数ごとの校正値になり MIP 相当ではない
- **レーザー出力の換算**: TUNE と信号振幅の関係はカメラ用可視光照明の
  ON/OFF などで変わるため固定の換算値は持たない。標準以外の振幅に
  合わせたいときはレーザーパネルの TUNE 最適化を使う

Phase 3 の**自動スキャンシーケンス**(位置スキャン / 2D ラスター / TUNE
エネルギースキャン) を内蔵。リアルタイム解析ツールは未実装 (Phase 4 後半で追加予定)。

## セットアップ (制御用 Windows PC)

```bash
pip install -r requirements.txt
```

追加インストールは不要 (`requirements.txt` の内容のみで動作する)。
NI-VISA や LeCroy VICP passport は **不要** — VICP は `lecroy_scope.py` に
純 Python で実装済み。VXI-11 を使う場合のみ `pyvisa` + `pyvisa-py` を使用する
(これも requirements.txt に含まれる)。

事前準備:

1. **PiLAS DX**: USB 接続には FTDI VCP ドライバが必要 (Product Guide 3.3節)。
   デバイスマネージャで COM 番号を確認する (解析用PCは **COM5**)。
2. **LeCroy**: オシロ側 Utilities → Utilities Setup → Remote の制御方式を確認。
   **TCPIP (VICP)** (既定) なら `VICP::<SCOPE_IP>::INSTR`、
   **LXI (VXI11)** なら `TCPIP0::<SCOPE_IP>::inst0::INSTR` を使う
   (どちらでも接続時にもう一方へ自動フォールバックする)。IP は <SCOPE_IP>。
3. **SHRC-203**: 本体メニューで Ethernet を有効化し IP <STAGE_IP> を設定。
   通信モードは SHOT 互換コマンドを想定。**ポート番号は本体設定に合わせる**
   (接続欄に `<STAGE_IP>:<ポート>` 形式で指定可)。
   **起動直後は必ず機械原点復帰 (GUI の「機械原点復帰 (H:W)」または JS-301 の M-ORG)**。
4. PC の IP を <PC_IP>、**サブネットマスク 255.255.255.0**、ゲートウェイ
   <GATEWAY_IP> に設定 (2026-10-23 に <OLD_SUBNET>.x から <LAB_SUBNET>.x へ移行。
   接続図 laser_setup.drawio 参照)。マスクを 255.255.255.255 にすると同一
   セグメントの機器にも直接届かずルータ経由になり、ステージが応答しない。

環境ごとの設定は `config_local.json` を作って上書きする (git 管理外推奨):

```json
{
  "laser_port": "COM5",
  "stage_um_per_pulse": [2.0, 2.0, 2.0],
  "stage_speed_pps": [1000, 10000, 200],
  "scope_save_dir": "C:\\Users\\<SCOPE_WIN_USER>\\Desktop\\data",
  "scope_smb_user": "<SCOPE_USER>",
  "scope_smb_password": "<SCOPE_PASSWORD>",
  "transfer_dest_dir": "..\\data"
}
```

波形の保存先 (オシロ本体側) は `scope_save_dir` をベースに日付で整理される:

```
<scope_save_dir>\<年>\<YYYYMMDD>\manual\                手動保存
<scope_save_dir>\<年>\<YYYYMMDD>\scan_<日時>_<モード>\   自動スキャン (1回毎)
```

自動スキャンのフォルダ名 (例: `scan_20260705_143022_1dY`) は PC 側の記録
CSV (`logs/scan_20260705_143022.csv`) と同じ日時スタンプなので対応付けできる。
フォルダはオシロ側に自動作成される。

## トラブルシューティング (2026-07 実機確認の症状と対処)

- **オシロ: 「接続中」になるのに設定が反映されない / 画面が映らない**
  → 旧版は通信できなくても接続扱いになることがあった。現在は接続時に
  `*IDN?` 応答を検証し、応答が無ければ VICP ⇔ VXI-11 を自動で試した上で
  エラーにする。リソース名は `VICP::<SCOPE_IP>::INSTR` を推奨
  (LeCroy の Remote 既定値 TCPIP(VICP) に対応。ping が通れば OK)。
- **ステージ: ping も通らない (IP 変更直後)** (2026-10-23 実機: <LAB_SUBNET>.x へ移行時)
  → PC のサブネットマスクが `255.255.255.255` になっていた。これだと PC は
  同一セグメントの機器にも直接 (ARP で) 届かず、全パケットをルータ
  <GATEWAY_IP> へ送る (`tracert <SCOPE_IP>` で 1 ホップ目に <GATEWAY_IP> が出る)。
  オシロは Windows でゲートウェイ設定があるためルータ経由でも返事できるが、
  SHRC-203 は同一サブネット以外へ返せず無応答になる。対処: PC のマスクを
  `255.255.255.0` にし、SHRC-203 本体も IP <STAGE_IP> / マスク 255.255.255.0 /
  ゲートウェイ <GATEWAY_IP> にして**電源を入れ直す** (Ethernet 設定は再起動後に
  有効)。同じ IP を使う機器が LAN 上に無いか (`arp -a`) も確認する。
- **ステージ: ping は通るが接続が timed out**
  → TCP ポート番号が本体設定と違う可能性が高い。実験室の実機は `9004`
  (2026-07 実機確認。GUI の既定値)。SHRC-203 本体メニューの
  Ethernet 設定でポート番号を確認し、接続欄に `<STAGE_IP>:<ポート>` を入力
  (Lantronix XPort 系の LAN 変換の場合は `10001` を試す。`23` は XPort の
  設定用 telnet ポートで制御には使えない)。他セッションの占有が疑われる
  場合はコントローラを再起動する。接続成立時は状態クエリ `!:` で通信確認
  し、無応答なら SHOT 互換モード/デリミタ (CRLF) の確認を促すエラーを出す。
- **データ回収: 「システム エラー 67」(ネットワーク名が見つからない)**
  → 2026-07-06 実機診断: ping は通るが SMB ポート (445/139) が両方閉じて
  おり、オシロ側 Windows がファイル共有を提供していない。オシロ本体を
  直接操作して (1) ファイルとプリンターの共有を有効化 (2) ファイア
  ウォールで共有を許可 (3) `scope_save_dir` のフォルダを共有名 `data` で
  共有 (<SCOPE_USER> に「変更」権限 — 削除に必要) する。PC 側は
  `config_local.json` の `"scope_smb_root": "\\\\<SCOPE_IP>\\data"`
  (設定済み)。手順の詳細は下記「データ回収の初期設定 (オシロ側)」参照。
  同日この手順で共有を作成し、初回回収 (7,178 ファイル / 4.6 GB) が
  成功することを実機確認済み。
- **カメラ: 真っ暗 / 真っ白にしか映らない**
  → カメラパネルの「ゲイン」を調整する (設定が効いたかは通信ログの実値で
  確認できる。実値が変わらなければカメラ側が非対応)。それでも駄目なら
  照明の明るさ・レンズの絞りを調整する。本機のカメラはオートフォーカス
  非対応 (手動フォーカスレンズ) のため、AF・露出の操作は GUI から削除した。
- **ステージ: 「機械座標: 不明」と表示され登録原点へ移動できない**
  → GUI が R:W を跨いで機械座標を追跡できていない (JS-301 から M-ORG した、
  コントローラを再起動した、原点復帰を途中で止めた等)。GUI の
  「機械原点復帰 (H:W)」を実行すると追跡が始まる。

```bash
python main.py              # 実機モード
python main.py --simulate   # 全デバイスをシミュレーション (ハード無しでUI確認)
```

## 使い方 (標準的な測定手順)

1. ツールバーの **センサー** で測定する DUT を選ぶ (初めての DUT は
   「編集...」→ 形状を入力 →「別名で保存」)。
2. **各パネルの「接続」** を押す (オシロ / ステージ / レーザー / カメラ)。
3. ステージパネルで **機械原点復帰 (H:W)** (起動後1回、干渉に注意)。
   GUI から実行すると機械座標の追跡が始まる。
4. ステージパネル [位置登録] の **「原点出し開始位置へ」** で前回登録した
   原点付近へ粗寄せする (初回・載せ替え後はカメラの**十字線**を目安に
   ジョグで基準ストリップ上・読み出し側端の 50〜200 µm 内側へ。
   **ピクセル型**は基準 CH のボンディングパッドの上または ±50 µm 以内へ)。
   ジョグの矢印は**カメラ画像上の移動方向**、ボタンの文字は実際に送る軸と
   符号 (▲ = Y−)。ステップ量は 2 µm〜5 mm から選択。
5. レーザーパネルの **「★ 標準設定を適用 ★」** で標準条件 (internal,
   1 MHz, TUNE manual 50 % = MIP 相当) を送信し、**発振 ON**
   (入力欄は接続時に実機の現在値へ同期される。別条件にするときは
   トリガーソース・繰り返し周波数・TUNE を個別に「設定」)。
6. オシロパネルで **ミラー開始** し波形を確認。
   **「★ 標準設定を一括適用 ★」** で標準条件 (EXT/DC/POS/410 mV,
   1 ns/div, 水平 -53 ns, C1–C4 50 mV/div +100 mV offset, D50) を送信。
7. ステージパネル [アライメント] の **「原点出し」** を実行 (フォーカス・
   電極中心 Y・外枠エッジ X を検出して R:W、原点の機械座標を自動登録)。
   載せ替え後は「フル較正」で傾き係数も取り直す。
   **ピクセル型**では手順が自動で切り替わる (パッドの Y ディップ → パッド横で
   Z → X ディップ → パッドの角で R:W。フル較正は他のパッドの平面フィット)。
8. 必要ならレーザーパネルの **TUNE 最適化** で目標振幅に合わせる。
9. 自動スキャンパネルで条件を確認し **スキャン開始**。進捗・残り時間は
   ツールバーに表示され、「中断」で止められる。
10. 異常時はツールバー右端の **■ 全停止** (タスク中断 → レーザー OFF →
    ステージ停止 → オシロ STOP)。

すべての送受信コマンドは左下の通信ログに表示され、`logs/gui_YYYYMMDD.log`
に記録される (測定ノート・トラブル解析用)。レーザー・オシロパネルには
コマンドコンソールがあり、GUI 未対応の操作も直接コマンドで実行できる。

## センサー / DUT の登録 (`sensors.py`, `logs/sensors.json`)

ボードやセンサーを変えたときにコードを編集しなくて済むよう、センサーごとの
プロファイルに次をまとめている。ツールバーの「センサー」で切り替えると、
スキャン既定範囲・傾き係数・登録位置・読み出し対応 (オシロパネルの
CH ラベル、ステータスバー) がそのセンサーのものに入れ替わる。

| 項目 | 内容 |
|---|---|
| 種類 | ストリップ / ピクセル (2026-10-16 追加)。原点出し・フル較正・既定スキャン範囲・「電極へ移動」・解析の種類が切り替わる |
| 形状 (ストリップ) | ストリップピッチ、電極 (金属) 幅、外枠エッジ→露出開始のオフセット、ストリップ露出長、端ギャップ |
| 形状 (ピクセル) | ピクセルピッチ、ボンディングパッド辺長 (無信号の正方形。原点出しの物差し) |
| 読み出し | オシロ CH ごとのパッド名・使用/未使用、基準 CH。ストリップ: 電極中心 Y (基準 CH を 0)。ピクセル: ピクセルの (列, 行) (基準 CH が (0, 0)、列は −X、行は −Y に +1。ピクセル中心 = (−パッド/2 − 列×ピッチ, −パッド/2 − 行×ピッチ)) |
| スキャン既定範囲 | 高速軸 Y / 低速軸 X の開始・終了・ステップ |
| フル較正の測定点 | ストリップ: X 測定点、Y 測定点 (「Y:CH」)、プローブ位置 (Z 測定・X 端検出の Y 離隔)、Y 掃引半幅。ピクセル: 基準以外の読み出しピクセルのパッド中心 (自動)、Z 測定の離隔、Y 掃引半幅 |
| 傾き係数 | dZ/dX, dZ/dY, dY/dX (フル較正 / 手動入力の結果。履歴は `sensor_calibration_<id>_<日時>.json`) |
| 登録原点 | 論理原点の機械座標 (原点出しのたびに自動更新) |
| 登録位置 | 名前 → 座標 (論理座標 / 機械座標) |

- **新しい DUT**: 似たセンサーを選んで「編集...」→ 形状と読み出しを書き換え →
  「形状から自動設定」でスキャン範囲と較正測定点を導出 →「別名で保存」。
- 初期登録は 4 件: 標準ストリップ (`scan_geometry.py` の実測値)、
  4col 1000 µm、可変ピッチ 500 µm 部、**ピクセル 2x2 (500 µm ピッチ、
  パッド 100 µm; 2026-10-15 の pixel#3 の配置)**。4col と可変ピッチは
  **ピッチ以外の寸法が未確認** (標準センサーの値を流用したひな形) なので、
  使う前に実測値へ編集すること。
- **ピクセル型の座標**: 論理原点 = 基準 CH のパッドの +X/+Y 側の角 (パッドは
  x, y ∈ [−パッド, 0])。ピクセル中心 = パッド中心。4 ピクセルの交点は
  (−パッド/2 − ピッチ/2, −パッド/2 − ピッチ/2)。解析 (tt_pixel.py) はパッドの
  位置を振幅から自動検出するので、原点が多少ずれていても結果は変わらない。
- 旧形式の `logs/sensor_calibration.json` と `logs/positions.json` は初回
  起動時に標準センサーへ移行される (元ファイルは残る)。
  `positions.json` のうち scan_geometry 由来のプリセットは移行せず、
  ユーザーが登録した位置だけ機械座標として引き継ぐ。

## ステージ: 位置登録と機械座標の追跡

- **座標系**: 表示・移動は論理座標 (論理原点 = 外枠エッジ・基準電極中心・
  合焦 Z)。その下に機械座標 (機械原点基準) を併記する。
- **機械座標の追跡**: R:W するとコントローラの座標は 0 に戻るため、
  「論理原点の機械座標」を GUI が積算して `logs/stage_frame.json` に保存する
  (H:W で 0 にリセット、R:W のたびに直前の座標を加算。GUI 再起動後も有効)。
  JS-301 から M-ORG した場合やコントローラ再起動後は GUI から H:W を
  やり直す。
- **原点の自動登録**: 原点出し (自動アライメント) が R:W まで完了すると、
  その論理原点の機械座標を現在のセンサーへ登録する。手動の
  「論理原点リセット (R:W)」は確認ダイアログのチェックで登録できる。
- **[位置登録] タブ**:
  - 「登録原点へ移動」「原点出し開始位置へ」: 機械原点復帰後の粗寄せ
  - 「ストリップへ移動」: CH と場所 (読み出し側端 / 中央 / 反対側端) を
    選ぶと、センサー形状と現在の傾き係数から座標を計算して移動する。
    ピクセル型では「ピクセルへ移動」(パッド横 (信号あり) / パッド中心 /
    4 ピクセル交点) になる
  - 登録位置の辞書: 現在位置を名前付きで登録 (論理座標 = センサー上の
    同じ場所を指す / 機械座標 = 原点を出す前の粗寄せ用)。ダブルクリックでも
    移動できる
- 移動はスキャンと同じ相対移動 (M:W) 方式。タスク (スキャン・較正など)
  の実行中はジョグ・移動・原点操作を無効化する (停止ボタンは常に有効)。

## 自動スキャン (Phase 3)

右カラムの「自動スキャン」パネルから実行する。シーケンスは仕様書 Phase 3 の
アルゴリズム (移動 → 整定 → スイープリセット → SINGLE 取得 → 完了待ち →
保存 → 次の点) を実装している。

| モード | 用途 | 既定値の由来 |
|---|---|---|
| 1D 位置スキャン | ストリップ横断 (Y: +750→-2250 µm = C0 外側→C5 外側, step 10 µm) | 2026-08-24 実測位置 (C0/C5 の外側半ピッチまで) |
| 2D ラスタースキャン | 横断 (Y) × 長手 (X: 0→-9370 µm = 端→スキャン終端, step 500 µm) の面スキャン (蛇行往復オプション付き) | 2026-08-24 実測位置 + TCT Scan プラン (スキャン領域 9.370 mm/strip) |
| 1D + TUNE | 1軸位置 × エネルギーの複合スキャン: **各位置で TUNE を掃引**する。位置が外側ループなのでステージ移動は位置が変わる時だけ。位置 step は広め (モード選択時に 50 µm へ自動変更) | 2026-07 プラン |
| TUNE スキャン | 固定位置でのエネルギースキャン | tune 50–90% (固定位置プラン) |

**センサー傾き補正** (1D/2D。係数は現在のセンサーのフル較正 / 手動入力値。
標準センサーで未較正なら `scan_geometry.py` の 2026-08-24 実測フィット):

- **回転追従 (Y)**: ストリップの面内回転 dY/dX に合わせて
  X スキャン開始位置を基準に Y をシフトする。どの X 行でもストリップが
  同じスキャン Y 座標に現れ、長手 1D スキャンでもストリップから外れない
  (標準センサーでは補正なしだと全長で ~72 µm ずれる)。
- **Z 追従** (フォーカス。2 µm/pulse 分解能) は 3 方式から選ぶ:

  | 方式 | 計算 | 使いどころ |
  |---|---|---|
  | 較正係数 (論理原点で合焦) **既定** | z = dZ/dX·x + dZ/dY·y (平面を論理原点に固定) | 原点出し直後の標準。**開始時にステージがどこにあっても同じ Z** になる |
  | 較正係数 (現在位置で合焦) | 同じ平面を開始時の現在位置に固定 (従来方式) | 手動でフォーカスを合わせた場所から始めるとき |
  | 実測 Z (始点・終点 / 四隅) | 1D: 始点と終点の合焦 Z を線形補間。2D: 四隅の合焦 Z を双線形補間 | 係数の較正をしていない DUT、較正結果が怪しいとき。**簡単で確実** |
  | なし | Z を動かさない | Z 自体をスキャンするとき等 |

  実測 Z 方式の手順: 方式を選ぶと始点・終点 (2D は四隅) の行が出る →
  各行の「移動」でその位置へ XY 移動 → Z ジョグまたは Z フォーカスで
  合焦 →「現在Z」で取り込む。値は論理座標の絶対 Z なので、スキャン開始時の
  ステージ位置には依存しない。
- 補正後の座標 (実際の移動目標) が CSV に記録され、方式・係数・実測 Z も
  ヘッダーに残る。開始確認ダイアログに Z の範囲と Y シフト量が表示され、
  最初の点の Z が現在の Z から 30 µm 以上離れていると警告が出る。

**データ健全性の確認**: ビーム半径は数 µm 以下なので、フォーカスが
合っていれば**電極 (ストリップ金属) 直上では信号がほぼ 0** になり、
電極端で急峻に立ち上がる。スキャン最初の行 (横断方向) でこれを確認する
こと。0 に落ちない/なだらかな場合はデフォーカスまたは座標ずれを疑う。

**スキャン開始時は必ず次の順序で自動実行される** (2026-07 実機デバッグで
確定した、不具合なく完了する流れ):

1. **オシロ設定変更** — アベレージングが ON なら **OFF** にする
   (リアルタイム波形でないとシーケンス/SINGLE の完了判定が機能しない。
   「アベレージング OFF」チェック既定 ON) → シーケンス設定 → 保存設定
   (連番は PC 側管理、下記)
2. **レーザー設定** (「開始時にレーザー ON」指定時の自動 ON)
3. **スキャン開始**

**画面ミラーリング**は止まらない (2026-09-07 変更): SCDP が危険なのは
シーケンス取得中だけなので、点ごとの「積算リセット〜保存」の取得
ウィンドウ中のみ自動で一時停止し、移動・整定中は再開される。ミラーを
開始しておけばスキャン中も点ごとに直前の取得波形が確認できる。

**保存ファイルの連番は PC 側で管理する** (2026-09-07 修正): オシロ内蔵の
連番カウンタ (EnableCounterSuffix) はカウンタが増えず**同名上書きで全点
消失**する事象が実機で発生 (2026-09-07 の 2 スキャン)。このため点ごとに
TraceTitle へ `scan--00042` 形式の連番を明示して保存する (ファイル名は
従来と同じ `C2--scan--00042.trc`、CSV の index と常に一致)。さらに
点ごとにオシロ側フォルダのファイル数を検証し、**2 点連続で増えなければ
スキャンを自動中断**してエラー表示する。

手順:

1. オシロ・ステージを接続 (TUNE スキャンはレーザーも)。チャンネル・
   トリガー (EXT)・タイムベースは先にオシロパネルで設定しておく
   (「★ 標準設定を一括適用 ★」には Averaging OFF も含まれる)。
2. **論理原点を決める**: ステージパネル [アライメント] の「原点出し」を
   推奨 (基準ストリップ付近に粗寄せするだけで、フォーカス・電極中心 Y・
   外枠エッジ X の検出から R:W まで自動)。手動の場合は基準ストリップ端
   付近へ移動 → Z フォーカス → 外枠エッジ相当 (信号エッジ +632 µm) で
   「論理原点リセット (R:W)」を実行し、そこを **(0,0,0)** とする。
   スキャン座標は**論理原点基準 (µm)** で入力し、ステージは
   **相対位置移動 (M:W)** で動く (絶対位置移動 (A:W) は不具合が
   あったため使わない。M-ORG 毎の絶対座標変化にも影響されない)。
   スキャン対象外の軸は開始時の現在位置に固定される (Z は Z 追従の
   方式に従う)。
3. シーケンス (既定 2000 seg/点 = 2000 events/step) と整定時間・
   点タイムアウトを設定。見積もり行に総点数×イベント数が表示される。
4. 「スキャン開始」→ 確認ダイアログ → 実行。進捗と残り時間はツールバーの
   タスク表示に出る。「中断」またはツールバー右端の「■ 全停止」で
   いつでも止められる
   (中断時はステージ停止 + オシロ STOP、自動 ON したレーザーは OFF に戻る)。

出力:

- **波形**: オシロ本体ディスク (保存先/prefix 指定、PC 管理の連番付き .trc 等)
- **座標記録**: PC 側 `logs/scan_YYYYMMDD_HHMMSS.csv`
  (index, x_um, y_um, z_um, tune_pct, status, timestamp)。
  座標は**傾き補正適用後**の論理座標 (実際の移動目標)。補正係数と
  開始時の基準位置はヘッダー行に記録される。
  オシロ側の連番ファイルと index で対応付けて解析する。
  status は ok / timeout (トリガー欠落等) / aborted。

## TUNE 最適化 — 40 MHz 以外で信号が消える問題への対処

**症状**: 繰り返し周波数を 40 MHz から変えると AC-LGAD 信号が全く
見えなくなる (2026-07 実機確認)。

**原因**: PiLAS の TUNE (発振の効き) の最適値は**繰り返し周波数に依存**
する。40 MHz で合わせた manual TUNE 値のまま周波数を変えると発振閾値を
下回り、光パルスが出なくなる。TRIG OUT は電気的に出続けるため
オシロのトリガーは掛かり続け、「波形は更新されるが平坦」になる。

**対処** (レーザーパネルの **TUNE 最適化**):

1. 周波数を変更したら、レーザー ON・フォーカス済みの状態で**方式**・
   CH・目標振幅を選び「最適化」を実行
2. TUNE を 100% (光が弱い側) から下げながら振幅 (PAVA) を測定し
   (粗掃引、既定 2% 刻み)、目標を跨いだ区間を **0.5% 刻み・多数回読み
   (中央値) で精密掃引**して **目標 ± 許容 (既定 ±1 mV) に最も近い TUNE に
   自動設定**、最後に検証測定する。数十秒〜1 分。中断・失敗時は元の
   TUNE に戻る (粗掃引だけだと ±数 mV の読み取りノイズで閾値交差が
   決まってしまうため。2026-10-05 の記録では隣接 TUNE 間で 65 → 77 mV
   と飛んでいた)
3. カーブは `logs/tuneopt_<日時>.csv` に記録 (phase = coarse / fine /
   verify、CH ごとの振幅・合計・ばらつき。その周波数での発振閾値も
   読み取れる)。目標未達なら振幅最大の TUNE に設定して警告を表示
   (その周波数の最大出力がエネルギー要件を満たすか判断する)。
   TUNE 100% (最弱) でも目標を超える場合は減光が必要と警告する

**方式** (2026-10-07 追加):

| 方式 | 測るもの | ビーム位置 | 目標の既定 |
|---|---|---|---|
| 単一 CH | 選んだ CH の振幅 (PKPK) | ストリップ横のシリコン上 (信号の見える位置) | 200 mV |
| 隣接 2ch 合計 (MIP 相当) | 隣り合う 2 ストリップを読む CH の振幅合計 **A_lead + A_sub** | **2 ストリップの中間** (ピッチ 500 µm なら電極から 250 µm) | **64 mV** |

隣接 2ch 合計は、AC-LGAD ではビームを 2 ストリップ間で動かしても
A_lead + A_sub の変化が小さい (電荷共有で分配されるだけ) 性質を使う。
ストリップ中間で合計を合わせれば**位置ずれに鈍感に MIP 相当の信号量へ
揃えられる**。目標値は DESY ビームテスト (2026) の結果: ストリップ中間
(y = 250 µm) で **64 ± 1 mV** (参考: ストリップ近傍の単一 CH で 77 mV)。
「2 ストリップの中間 Y へ移動して測定」(既定 ON) にすると、選んだ CH 組の
電極中心の中間 Y へ**現在の X のまま**自動移動 (面内回転 dY/dX で Y を、
チルト dZ/dY で Z を現在位置から相対補正) してから測り、終了・中断後に
元の位置へ戻る (ステージ接続が必要。現在位置で合焦していること)。
OFF なら現在位置で測る (手動でストリップ中間へ置いておく)。CH 組は
センサープロファイルの読み出し電極 Y から隣接するものだけを列挙する。

簡易確認としてレーザーパネルで TUNE を **auto** モードにする手もある
(コントローラが周波数ごとの校正値を使う) が、波高を揃えたい測定では
TUNE 最適化で目標振幅に合わせる方が確実。

## Z オートフォーカス (波形振幅ベース)

**★フォーカスの前提 (2026-09-07 実測で訂正)★**: フォーカスが合うほど
振幅は**小さく**なる — 局所キャリア密度増による LGAD ゲイン抑制
(プラズマ効果)。カメラでフォーカス最良のとき振幅は最小だった。
旧方式「振幅最大 = 焦点」は誤り。掃引は**信号が明瞭に見えるストリップ
横のシリコン上**で行う (電極は幅 ~50 µm あり、直上ではデフォーカス
してもスポットが金属内に収まったまま振幅 0 で谷が見えない —
2026-09-07 実機確認)。ゲイン抑制の谷は浅い (数十 %) ため、50% 閾値の
両翼エッジの中点で谷中心を決める。

使い方 (ステージパネル [アライメント] タブ。通常は「原点出し」がこの処理を
内包するのでそちらを推奨。実測 Z 方式の端点合わせにも使う):

1. レーザー ON・**ビームをストリップ横のシリコン上** (信号が明瞭に
   見える位置。電極直上は不可) に置く。オシロで信号確認
   (トリガー EXT, NORM で波形更新)
2. CH・範囲 (既定 ±20 µm)・step (既定 2 µm = Z 分解能)・方式
   (既定「振幅最小 (焦点)」) を選び「Z フォーカス」→ 下から一方向で
   掃引 (バックラッシュ対策) → 谷の中心の Z へ自動移動。約 20〜30 秒
3. そのままスキャン開始する場合は Z 追従を「較正係数 (現在位置で合焦)」に
   するとこの Z を基準面として全域に展開する
4. 掃引カーブは `logs/autofocus_<日時>.csv` に記録。「谷を特定できない」
   と出たら範囲を広げる (±30〜50 µm)・電極直上に置き直して再実行

実行中はシーケンス OFF・トリガー NORM に切り替わる (スキャン開始時に
再設定されるため戻す必要はない)。中断・エラー時は元の Z に戻る。

## 自動アライメント (信号ベース, 2026-09-07 追加)

「カメラでストリップ中心をメモ → scan_geometry.py を編集」の手作業を
不要にする機能。**レーザー誘起信号そのものを位置センサーとして使う**:
金属電極上では信号がゼロになり、エッジはビーム半径 (数 µm) で切れる
ため、振幅プロファイルのディップ/エッジが µm 精度の物差しになる
(gui/alignment_worker.py。振幅読みは Z オートフォーカスと同じ PAVA)。

操作はステージパネルの [アライメント] タブ。測定点・オフセットは現在の
センサープロファイルから来る (以下の数値は標準センサーの例)。

**事前準備**: [位置登録] の「原点出し開始位置へ」またはカメラで、基準 CH
(標準は C1) のストリップ上、露出部の読み出し側端 (②/③境界) から
50〜200 µm 内側にビームを置く (±100 µm の粗寄せで十分)。
レーザー ON・トリガー EXT で信号が見えている状態にする。

原点出し済みの状態 (ステージが論理原点 = 外枠エッジ上で信号なし) から
続けてフル較正や原点出しのやり直しをするときは、**「論理座標の開始位置へ
自動移動」** にチェックを入れると、現在の論理原点を基準に開始位置
(基準ストリップ上・端から 100 µm 内側) へ移動してから始まる。

**原点出し (毎回の測定前。粗検出のみ 約 2〜3 分、精密仕上げ+検証 ON で
約 7〜12 分)**:
①Y 粗掃引で電極ディップ検出 → ②**電極から 80 µm 横のシリコン上で
振幅最小の Z (= 焦点)** (上記の訂正済み前提。谷が掃引の端にかかったら
自動で再センタリング) → ③Y 精密掃引で電極中心 (C1) を確定 →
④X 掃引 (+側=パッド領域へ) で信号消失エッジ (②/③境界) を検出 →
⑤シリコン上で Z 再確認 →
**エッジ +632 µm (設計オフセット ⓪+①+② = 外枠 GND エッジ) へ全軸を
負側から進入して論理原点リセット (R:W) まで自動実行**し、論理原点の
機械座標を現在のセンサーへ自動登録する。
以降のスキャン座標はこの論理原点 (外枠エッジ) 基準で、標準センサーでは
**X=−10 mm がギャップ④中央 (ストリップ領域の境界)** になる。

**精密仕上げ+検証 (2026-10-05 追加, 既定 ON)**: 上記の③④⑤の後に、
各量を**ステージの 1 パルス (2 µm) 刻み・1 点 4 回読み (中央値)** で
掃引し直してモデルフィットでサブ µm に決める:
- Y 電極中心: 両エッジを個別に erf (誤差関数) フィット (高原の勾配と
  エッジ直前の振幅増強を一次項で吸収) → 中点。2 回掃引して差を再現性と
  して表示。さらに逆方向 (降順) に 1 回掃引し、昇順との中心差を
  **バックラッシュ推定**として表示する (原点は昇順進入で決める)
- X 信号エッジ: 同じ erf フィット、2 回 + 逆方向 1 回
- Z 焦点: 谷を**ローレンツ型 + 一次基線**でフィットし、曲線の最小点を
  焦点とする (2026-10-05 実機データで同一箇所の 2 回測定が 0.1 µm 以内に
  一致。旧 50 % 閾値法は 0.4〜0.7 µm ばらついた)。プローブ位置 (電極横
  80 µm) → 電極中心上への換算は現在の傾き係数で補正 (標準で 0.3 µm)
- ⑥**検証**: R:W の後に電極中心 Y・信号エッジ X・焦点 Z を同じ精密掃引で
  再測定し、残差が 1 パルス以上の軸があれば補正して R:W をやり直す
  (最大 2 回)。最終残差・バックラッシュ推定・フィット誤差は完了
  ダイアログと `logs/sensor_calibration_*.json` (フル較正時) に残り、
  全掃引の生データは `logs/alignment_<日時>.csv` に記録される。
  1 µm 未満の残差は 2 µm パルス格子の丸め残りで、これ以上は詰められない
- 記録する位置は指令値ではなく実際のパルス格子に丸めた値 (3 µm
  ステップは 2 µm 格子に丸まるため、指令値のままだと最大 1 µm の
  鋸歯状誤差が乗る)

2026-10-05 の実機ログ (2 回のフル較正) を解析した結果、閾値法と erf
フィットの電極中心は 0.3 µm 以内、X エッジは 0.5 µm 以内で一致し、
**信号ベースの測定自体は 1 µm 以下で自己整合**している。手動 (カメラ)
原点との数 µm の差は、カメラ十字線とレーザースポットのオフセット、
パッド端→外枠端の設計値 632 µm の実寸との差、進入方向 (バックラッシュ)
といった**基準の定義差**によるものと考えられる。X の設計値はセンサー
編集の「外枠エッジ→露出開始オフセット」で実寸に合わせられる。

**フル校正 (載せ替え・治具変更時。粗 約 8〜12 分、精密 約 15〜25 分)**:
原点出しの後、
X = −5.3 / −9.9 mm で電極中心とフォーカス Z、Y = C2 / C4 電極で
電極中心とフォーカス Z を実測し、**dY/dX (回転)・dZ/dX・dZ/dY (チルト)
を直線フィットして現在のセンサープロファイルに保存**する
(履歴は `logs/sensor_calibration_<センサーID>_<日時>.json`)。
隣接電極間隔の実測値と**直線フィットの残差**も結果に表示される。
精密仕上げ ON では各測定点の電極中心と焦点 Z も 1 パルス刻みの
フィットで決める。X 測定点の Z は電極線 (Y が dY/dX で流れる) に沿って
測るため、その傾きから dZ/dY·dY/dX の結合項を除いたものを dZ/dX とする
(スキャンの平面モデルは Y 一定の偏微分を使う。標準センサーで 0.03 µm/mm)。
Z は 2 µm 刻みでしか決まらず谷も浅いので、Z の残差が数 µm を超える・
係数が前回から大きく動いた場合は鵜呑みにせず、再実行するか
スキャンの Z 追従を「実測 Z」方式にする。

**係数の優先順位**: センサープロファイルの係数 (フル較正 / 「係数を手動
入力...」) → 標準センサーのみ `scan_geometry.py` (2026-08-24 カメラ実測の
既定値) → それ以外の未較正センサーは 0。現在有効な係数と出典は
ステージパネル [アライメント] と自動スキャンパネルの「傾き補正」欄の
両方に表示され、較正・手動入力・センサー切り替えのたびに更新される。

注意: フォーカス測定は電極中心から 80 µm 横、**X エッジ検出は 50 µm 横**
のシリコン上で行う (80 µm だとボンドパッドの Y 幅から外れて信号が
消えず「明確なエッジがない」になった — 2026-09-07 実機確認)。
「明確なディップ/エッジがありません」「谷が浅すぎます」と出た場合は
ビーム位置とフォーカスを確認して再実行する。フル校正の各測定点も
「ディップ検出 → シリコン上で Z 最小化」の順で動く。

## データ回収 (オシロ → PC, SSH/SFTP)

スキャンの波形はまずオシロ本体ディスクに保存される。自動スキャンパネルの
[データ回収] タブで、**日付を指定して**
`<scope_save_dir>\<年>\<YYYYMMDD>` フォルダを丸ごと PC 側
`<transfer_dest_dir>\<年>\<YYYYMMDD>` (既定はリポジトリ隣の `data\`) へ
回収できる (2026-09-07 に SMB 方式から仕様変更。ターミナルの
`scp -r <SCOPE_USER>@<SCOPE_IP>:C:\...\20260907 .` と同じ SSH/SFTP
プロトコルで、SMB + SHA-256 検証方式より大幅に速い)。

- **接続**: オシロ側の OpenSSH サーバへ `scope_smb_user` (既定
  **<SCOPE_USER>**) で SSH 接続する。**パスワードは保存せず転送のたびに
  入力する** (入力ダイアログ。同一セッション中は前回値がプリフィル
  される)。
- **日付指定**: 既定は今日。過去の日付フォルダも指定可能。
- **重複スキップ**: PC 側に同名・同サイズで存在するファイルは自動
  スキップ。スキャンフォルダ内の全ファイルが回収済みなら
  「回収済みフォルダ n 個をスキップ」と報告される (再実行は安全)。
  同名で**サイズが違う**ファイルは上書きせず「競合」として報告する。
- **検証**: 転送後にファイルサイズを照合する (SSH/TCP の伝送整合性 +
  サイズ確認。旧方式の SHA-256 再読込は廃止 — これが速さの理由の一つ)。
- **削除** (既定 **OFF**): 「転送後にオシロ側を削除」を ON にすると、
  エラー・競合・中断が 1 件もなくサイズ検証済みの場合に限り、オシロ側の
  元ファイルを削除し空フォルダを片付ける (容量確保)。
- 結果 (パス, サイズ, 状態, 削除有無) は
  `logs/transfer_YYYYMMDD_HHMMSS.csv` に記録される。
- スキャン実行中は転送できない (GUI 上で排他)。オートセーブ動作中の
  転送も避けること。

前提 (初回のみ): オシロ側 (Windows) で OpenSSH サーバ (sshd) が有効に
なっていること (2026-09 時点の実機は設定済みで、ターミナルからの scp
接続を確認済み)。旧 SMB 方式の実装は `devices/scope_files.py` に残して
あるが GUI からは使われない。

## 取得データの簡易解析 (`analysis\` / GUI の「解析」タブ)

回収済みスキャンデータの解析パッケージを `analysis\` に同梱している。
スキャンの種類 (1dX / 1dY / 1dZ / 2dYX / tune / 1d_tune) をログ CSV から自動判別し、種類ごとの
解析コードで、解析ノート matome と同じ定義の図と数値 (振幅・電荷、立ち上がり、ジッター、
位置分解能、時間分解能、伝搬) を出力する (2026-10-05 更新)。
.trc → 単一 ROOT ファイル変換 (`--root`) も可能。

GUI からも実行できる: メインウィンドウの **「解析」タブ** で
スキャンを選んで「解析開始」(従来の制御画面は「制御」タブにそのまま)。
解析はサブプロセスとして走るため測定中でもブロックせず、中断・
進捗表示・完了後の図プレビュー・結果フォルダを開く、ができる。

コマンドラインからは:

```bat
cd analysis
python run_analysis.py scan_20260826_152932_2dYX --root
```

出力はリポジトリの外: 図・CSV は `<workspace>\results\<スキャン名>\`、
ROOT はスキャンフォルダの隣 (`<scan_dir>.root`)。詳細は
[analysis/README.md](analysis/README.md)。

## 既知の要確認事項 (実機での初回動作時)

- **`stage_um_per_pulse` の校正**: X/Y は 2 µm/pulse を実機確認済み
  (2026-07: 100 µm 指定で 200 µm 移動していたため 1.0 → 2.0 に修正)。
  **Z 軸は未確認**なので、初回は小ステップでジョグして実移動量を確認する
  こと (誤設定のまま大ステップを使うと対物レンズ衝突の危険)。
- SHRC-203 の Ethernet ポート番号 (既定 9004, 2026-07 実機確認) とコマンドモード
  (SHOT 互換/専用) はコントローラ側設定に合わせる。
- LeCroy の `VBS 'app.SaveRecall...'` 系はファームウェアにより
  プロパティ名が異なる場合がある。動かない場合はコマンドタブから
  `VBS? 'return=app.SaveRecall.Waveform.WaveFormat'` 等で確認する。
- PiLAS の COM ポート番号、カメラのデバイス番号。
